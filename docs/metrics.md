# 指标口径

## 统计对象与日期

- **收录池**：`applications` 中已收录的仓库，以 GitHub repository ID 去重，仓库改名不产生新项目。
- **正式统计池**：`kind='application' AND evidence_level='explicit'`。其他候选仍可查看和复核。
- **创建时间**：来源仓库的 `created_at`；不等于产品上线时间。
- **首次收录**：平台第一次发现该项目的 `first_seen_at`，不因再次采集改变。
- **采集时间**：`observed_at` / `last_observed_at`，用于说明数据新鲜度。
- **观测覆盖天数**：正式统计池实际存在快照的不同日期数；不把最早到最晚日期之间的缺采集日算入覆盖。
- **统计日**：统一 UTC。`as_of` 为已保存快照的最大日期；无快照时使用当前日期，仅代表查询基准，不代表已采集数据。

7/30/90 天筛选包括 `as_of` 当日及之前的 6/29/89 天。星标净增使用 `as_of` 与恰好 7/30 天前两个时点，因此七天净增需要跨越七个完整日间隔。

## 星标与增长

| 指标 | 定义 | 缺失处理 |
| --- | --- | --- |
| 当前 stars / forks | 优先使用 `as_of` 当日快照；该日缺失时展示最近业务实体上的计数及采集时间 | 不能因此补出净增 |
| `growth_7d` | `stars(as_of) - stars(as_of - 7 days)` | 任一精确边界快照缺失则 null |
| `growth_30d` | `stars(as_of) - stars(as_of - 30 days)` | 同上 |
| 每日观测 stars | 当日成功观测的正式统计池应用的 stars 之和 | 同时显示实际观测应用数 |
| 每日总 growth | 当前正式统计池在相邻两日的总 stars 差 | 只有整个当前统计池在两日均有快照时返回，否则 null |

每日只保留每个项目最后一次成功观测，界面更新当天结果时可以发生变化。掉星导致负净增是合法数据，不做归零处理；null 表示未知，零表示真实观测结果无净变化。

类别与资格采用**当前分类状态**。修改分类会重算历史图中的当前统计池，并不还原过去某天“当时已被认定合格”的成员关系。页面展示的是当前收录池的历史观测，不应拿它宣称同期全市场规模。

## 分布与讨论

- 类别占比 = 该类别正式统计池项目数 ÷ 正式统计池总数；未知类别进入分母。
- 工具占比 = 使用该工具的正式统计池项目数 ÷ 正式统计池总数。一个项目可以使用多个工具，同一项目重复工具标签先去重，所以各工具百分比相加可以超过 100%。工具列表为空时进入 `未知`。
- HN score 与评论数是采集时的当前值。没有采集前的历史分数曲线。讨论按明确 GitHub URL 或确定链接关联，不用标题相似度自动合并不同产品。
- GitHub 星标净增与 HN 讨论分开呈现；它们不等同用户量、收入或产品质量，也不直接相加生成跨平台分数。

## 覆盖范围与首日体验

GitHub 搜索是候选发现机制，存在每次搜索最多 1000 条、接口限流和 `incomplete_results`。HN 官方 new/show 列表有长度上限，不覆盖全部历史发帖。每轮查询的来源、时间、状态与覆盖信息应保留，统计不代表全网普查。

live 首日可以展示当前总量、应用详情、近期创建/收录分布；七天与三十天净增显示历史不足。demo 的历史数据由固定种子生成，单独运行，不写入 live 数据库。第一版不依赖 star history 回填接口。

## 周报口径

报告保存统计起止日、事实集与来源链接。SQL 负责数量、榜单、增量与占比；AI 用这些事实组织解释，不计算新数字，也不推断因果关系。增长榜仅包含拥有精确七天边界的项目，并展示完整窗口项目数 / 当前正式统计池规模；缺历史的新项目不参加增长排名。整个统计池的净增只有全池边界齐全时给出。完全没有可比较项目时生成观察摘要。七个观察日使用 as_of-6 至 as_of，七天净增的基线为 as_of-7，两种日期同时保存在报告事实中。
