# 分类质量评估

`cases.json` 包含 40 条手工定义的**合成规格案例**，用于检查：作者开发声明、仅接入 AI 功能、工具提及、否定表达、资源集合、开发工具、中文声明和多工具归属。期望标签逐条显式保存，测试不会从分类器生成标签。

```sh
backend/.venv/bin/python data/evaluation/evaluate.py
```

结果写入 `results.json`，记录真实执行时间、逐字段准确率、明确开发声明的 precision/recall 和逐条差异。此评估只测试规则基线，不访问模型 API。

这些数字是合成案例上的规格符合度，**不能用于宣称真实仓库准确率，也不能称为已完成的人工真实样本评估**。上线后请从已采集项目中抽取至少 30 条，在不查看模型预测的情况下人工核对 README 声明、作品类型和工具归属，再以真实标签重复评估。`human-review-template.csv` 是独立的待审核表。

## 真实公开来源的 agent 审读

`real-agent-cases.json` 保存 32 个实际 GitHub 项目的来源、短摘录、逐条审读理由、agent 标签及规则预测快照。审读覆盖项目描述、README 简介和候选开发声明；标签明确为 `agent_reviewed`，**不是人类标注**。类型标签区分最终用户应用、开发工具和资源；开发证据仅判断是否发现作者对本项目的明确声明。

```sh
backend/.venv/bin/python data/evaluation/evaluate_real_snapshot.py
```

此命令重新计算已保存的预测快照。README 可随时间变化，脚本不会悄悄重新抓取内容或调用模型。评估结果保存在 `real-agent-results.json`，包含修正前后的表现与剩余类型分类错误。

这批样本用于发现问题并改进规则，**是开发集，不是独立测试集**；正例较少、采样不随机，不能据此声称全网或上线准确率。样本暴露了旧采集顺序偏向较早日期分区的问题，生产采集已改为声明查询优先、最新日期分区优先。人类审核仍使用上方独立模板。

`live-smoke-results.json` 另记录小样本真实 GitHub／HN 数据经过采集、入库、分类、指标和周报的端到端验证，使用匿名请求与独立临时数据库，未混入演示数据。
